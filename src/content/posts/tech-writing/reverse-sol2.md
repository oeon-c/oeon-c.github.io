# Windows Solitaire 승리 조건 패치

## 1. 패치 목적

기존 Windows Solitaire(`SOL.EXE`)의 승리 조건을 수정하여, **4개의 파운데이션에 각각 1장 이상의 카드가 존재하면 승리하도록 변경**하는 것을 목표로 한다.

IDA Free를 사용하여 기존 승리 판정 코드의 비교값과 조건 분기 명령어를 수정하고, 실제 게임 실행을 통해 패치 결과를 검증하였다.

## 2. 1차 패치: 비교값 변경

### ① 기존 코드

승리 판정 함수에서 다음 명령어를 패치 대상으로 선정하였다.

```asm
cmp eax, 0Dh
jnz loc_401BC8
```

- `cmp eax, 0Dh`: EAX의 값이 13인지 비교
- `jnz loc_401BC8`: EAX가 13이 아니면 승리 처리 없이 함수 종료

### ② 비교값 수정

IDA에서 비교 명령어가 위치한 `0x401AED`로 이동한 후 다음 메뉴를 선택하였다.

`Edit → Patch program → Assemble`

기존 비교값 `0Dh`를 `1`로 변경하였다.

```asm
; 패치 전
cmp eax, 0Dh
jnz loc_401BC8

; 1차 패치 후
cmp eax, 1
jnz loc_401BC8
```

비교값을 변경한 후 `Edit → Patch program → Apply patches to input file`을 사용하여 수정 내용을 실행 파일에 반영하였다.

### ③ 실행 결과

패치한 실행 파일을 실행한 결과, 파운데이션에 카드가 존재하는 상황에서도 승리 메시지가 출력되지 않았다.

실행 당시 파운데이션에 쌓인 카드 수는 다음과 같았다.

| 파운데이션 | 카드 수 |
|---|---:|
| 하트 | 2장 |
| 스페이드 | 1장 |
| 다이아몬드 | 3장 |
| 클로버 | 1장 |

### ④ 실패 원인

1차 패치에서는 비교값만 변경하고 조건 분기 명령어 `jnz`를 그대로 유지하였다.

`jnz`는 비교한 값이 같지 않을 경우 분기하는 명령어이다.

따라서 수정한 코드는 다음과 같이 동작한다.

```c
if (count != 1) {
    return;
}
```

즉, **카드가 1장 이상일 때가 아니라 정확히 1장일 때만 조건을 통과**하게 된다.

실행 당시 하트와 다이아몬드 파운데이션에는 각각 2장, 3장의 카드가 존재하므로 승리 조건을 충족하지 못한 것으로 판단하였다.

## 3. 2차 패치: 조건 분기 변경

### ① 패치 방향 수정

1차 패치 결과를 바탕으로 비교값뿐 아니라 조건 분기 명령어도 수정해야 한다고 판단하였다.

목표는 EAX가 정확히 1일 때만 통과하는 것이 아니라, **EAX가 1 이상이면 통과하도록 변경**하는 것이다.

이를 위해 `jnz`를 `jl`로 변경하였다.

### ② 패치 코드

```asm
; 1차 패치
cmp eax, 1
jnz loc_401BC8

; 2차 패치
cmp eax, 1
jl loc_401BC8
```

각 명령어의 차이는 다음과 같다.

| 명령어 | 분기 조건 | 의미 |
|---|---|---|
| `jnz` | EAX ≠ 1 | 정확히 1이 아니면 종료 |
| `jl` | EAX ＜ 1 | 1보다 작으면 종료 |

`jl`은 부호 있는 정수 비교에서 왼쪽 값이 오른쪽 값보다 작을 때 분기하는 명령어이다.

따라서 EAX가 1 이상이면 분기하지 않고 다음 명령어를 실행한다.

변경된 조건을 C 코드로 표현하면 다음과 같다.

```c
if (count < 1) {
    return;
}
```

4개 객체 모두 이 검사를 통과하면 승리 처리 코드가 실행된다.

### ③ 실행 파일에 패치 적용

IDA에서 다음 순서로 패치를 적용하였다.

1. 승리 판정 함수의 조건 분기 명령어로 이동
2. `Edit → Patch program → Assemble` 선택
3. `jnz loc_401BC8`을 `jl loc_401BC8`로 수정
4. 변경된 명령어 및 분기 대상 확인
5. `Apply patches to input file`로 실행 파일에 반영
6. 수정된 `SOL.EXE` 실행

## 4. 패치 결과 검증

### ① 실행 결과

2차 패치를 적용한 후 게임을 실행하여 파운데이션에 카드를 배치하였다.

실행 당시 파운데이션 상태는 다음과 같았다.

| 파운데이션 | 최상단 카드 | 카드 수 |
|---|---|---:|
| 하트 | 2♥ | 2장 |
| 다이아몬드 | A♦ | 1장 |
| 클로버 | 3♣ | 3장 |
| 스페이드 | A♠ | 1장 |

모든 파운데이션에 최소 1장 이상의 카드가 존재하는 상태에서 다음 메시지가 출력되었다.

**「축하합니다!!」**

이는 기존의 정상적인 승리 조건인 파운데이션별 13장 완성 없이 승리 메시지가 출력된 결과이다.

### ② 패치 전후 비교

| 구분 | 기존 프로그램 | 1차 패치 | 2차 패치 |
|---|---|---|---|
| 비교 명령어 | `cmp eax, 0Dh` | `cmp eax, 1` | `cmp eax, 1` |
| 조건 분기 | `jnz` | `jnz` | `jl` |
| 검사 통과 조건 | EAX = 13 | EAX = 1 | EAX ≥ 1 |
| 실행 결과 | 정상 승리 조건 검사 | 승리 메시지 미출력 | 승리 메시지 출력 |

## 5. 결론

이번 실험에서는 IDA Free를 이용하여 Windows Solitaire의 승리 조건을 수정하였다.

처음에는 비교값을 13에서 1로 변경하였으나, 기존 조건 분기 명령어인 `jnz`가 유지되어 정확히 1장인 경우만 검사를 통과하는 문제가 발생하였다.

이를 해결하기 위해 조건 분기를 `jl`로 변경하였다. 그 결과 반환값이 1 이상이면 검사를 통과하도록 수정할 수 있었다.

실제 게임 실행에서 네 파운데이션의 카드 수가 각각 2장, 1장, 3장, 1장인 상태로 **「축하합니다!!」 메시지가 출력되는 것을 확인하였다.**

이를 통해 비교 명령어와 조건 분기 명령어를 함께 수정하여 프로그램의 승리 판정 동작을 변경할 수 있음을 검증하였다.

다만 이번 실험은 승리 메시지 출력 여부를 중심으로 검증하였으며, 점수 처리 및 게임 종료 상태까지 기존 승리와 완전히 동일하게 동작하는지는 별도로 확인하지 않았다.
